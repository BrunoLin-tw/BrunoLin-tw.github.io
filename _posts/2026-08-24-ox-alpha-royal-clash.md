前幾天研究那個突然冒出來的匿名推理模型 Ox Alpha（代號「牛來」），順手拿它做了一個小東西：模仿 Clash Royale 玩法、以 Canvas 開發的網頁即時對戰遊戲，命名「皇室爭霸」。

遊戲（here.now）：https://oaken-haven-wht4.here.now/
原始碼：https://github.com/BrunoLin-tw/clashroyale

## 為什麼會想用它刻遊戲

一開始只是測試長 context 工具鏈。1M token 的上下文窗口拿來寫遊戲腳本很奢侈——可以一口氣把所有卡牌邏輯、精靈動畫、碰撞判定全部丟進去，不用擔心 prompt 爆掉。實際跑下來，遊戲主邏輯大約 600 行 JS，一次對話就生完了，中間還能即時調整規則。

長 context 在 agent 工作流裡真正的用處是：讓模型一次掌握完整系統上下文，減少來回拆解、確認、修正的成本——而不是拿來總結一本書。

## 遊戲內容

目前版本功能：

- 4 張卡牌，數字鍵 1-4 或滑鼠點選切換
- 移動滑鼠調整攻擊目標，左鍵部署單位或法術
- 右鍵或 ESC 取消選取
- 3 分鐘倒數，先推倒對手國王塔者獲勝
- 特殊取勝方式：把國王塔拉到橋頭（某些對戰地圖）

純 client-side，無後端，音效用 Web Audio API 即時合成。視覺風格走低多邊形卡通路線，規格相對輕量。

## 拿 Ox Alpha 開發的實際感受

用這個模型跑 agent 工作流和用一般模型最大的差異是：它真的會把整個系統放在心裡。

舉例來說，我請它加入一套「法術剋制」規則——火球打地面單位、冰雪緩速、閃電暈塔——它直接理解了三者的使用時機邏輯，而不是各別翻譯成一條條獨立的 if-then。這個上下文保留能力，在 600 行級別的單次輸出裡感受明顯。

缺點也有：高推理檔位有時會「過度思考」，少數情況下卡在 reasoning 階段不吐出結果，要重新送一次。免費期的穩定性像抽獎，生產環境還不能押。

## 8/28 是關鍵日期

Ox Alpha 的身份至今仍是謎，社群指紋指向智譜 GLM-5.3，8/28 那天 GLM-5.3 權重開源，答案應該就揭曉了。免費預覽期還沒過，玩的可以繼續玩，但別拿它跑真的營運。

遊戲本身是一個 side project，純粹拿來驗證 long-context agent 工作流的實際瓶頸在哪。如果只是要快速原型驗證，用它還算順手。
